# LABJUDGE-EXT09 三草案判定

## 案①：CIRC重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线选择：稳健，但依赖“探针隔离”被执行到位。**
把 C 降级为探针、以 B 的见证证书化为内嵌 A 的载体，方向正确：它把“可信性”从口头声明转成可携带的凭证结构，同时避免 C 反向污染主线。AC1–AC5 若覆盖“证书生成—绑定—验证—失效—重放抵抗”五段，路线是收敛的。

**机器复核：可，前提是 AC 写成判定式。**
AC 必须避免“合理性/充分性”类形容，改成布尔谓词（存在性、哈希绑定、签名可验、时间/序号单调、负例必须 fail）。否则 AC 只是人评清单。

**制度漏洞：两处。**
- **探针越权**：C“仅探针”需明文禁止其输出进入 A/B 的证成链，否则探针事实上变成第二主线。
- **证书≠正确**：证书化只证明“谁在何时以何参数产出何结果”，不证明结果正确；A 内嵌时若把“有证书”当“已确权”，会把认证偷换成正确性认证（与案②同源风险）。

**票：不反对。**

## 案②：缓存锚域限条款（fallthrough DONE 四条件 + BLOCKED 四触发 + 缓存锚≠内容认证）

**路线选择：必要且正确，但边界设计是本三案最大风险点。**

**DONE/BLOCKED 边界的机器复核性：**
- 四条件若为合取式（AND）且每条可判真伪，则可机器复核。
- 四触发若为析取式（OR）且任一条可判真伪，则可机器复核。
- **致命点**：若 DONE 与 BLOCKED 不是**互斥且穷尽**（MECE），会出现“同时 DONE 且 BLOCKED”或“既不 DONE 也不 BLOCKED”的悬空态。必须补：
  - 优先级规则（BLOCKED 优先于 DONE，还是反之）；
  - 悬空态的默认归属（建议默认 BLOCKED，安全侧）；
  - 四条件/四触发的判定时点（T 时刻判定，还是持续判定）。

**“缓存锚≠内容认证”**：这是本条款最关键的防漏洞声明，方向完全正确。它切断了“锚定存在→内容可信”的跃迁。但需警惕实施层的**隐含再认证**：fallthrough DONE 若被下游当作“内容已认证”使用，则声明形同虚设。建议加一条**下游禁用条款**：DONE 仅表示锚域限达成，不得作为内容认证凭据引用。

**制度漏洞：**
- DONE 四条件未给“条件失效后是否回退”的规则（单调性缺失）。
- BLOCKED 四触发未给“解除触发后的恢复路径”，可能造成永久 BLOCKED。
- 缓存锚的**域限**未定义域边界（时间域？键域？版本域？），域不清则“限”不可复核。

**票：不反对，但附强制修订建议（MECE + 优先级 + 时点 + 禁用条款）。**

## 案③：A1堆叠升级（L0确权锁边界，L1/L2契约JSON化，DISPUTED停层）

**路线选择：稳健，分层清晰。**
L0 确权锁边界 + L1/L2 契约 JSON 化 + DISPUTED 停层，是标准的分层治理结构。JSON 化使契约可机器解析，方向正确。

**机器复核：可，前提是 JSON Schema 固化。**
需给出 L1/L2 的 schema（必填字段、类型、枚举、互斥约束），否则“JSON 化”只是格式统一，不是契约可验。

**制度漏洞：层级停让规则是弱点。**
- **DISPUTED 停层**：需明确“停在哪一层”——是停 L1 不上浮 L2，还是全层冻结？未定义则争议期行为不确定。
- **L0 锁边界**：需明确 L0 锁是“禁止修改”还是“禁止未授权修改”，二者安全语义不同。
- **停让规则缺失**：L1 与 L2 冲突时谁让谁？DISPUTED 时是否允许 L0 继续？需给出**层级优先序 + 争议期降级规则**。
- **升级不可逆风险**：L0→L1→L2 升级若不可回退，一次误升级即永久污染；需定义回退/降级路径。

**票：不反对，但附修订建议（停层语义 + 层间优先序 + 回退路径 + schema 固化）。**

**总判定：pass（附条件）**

**理由：** 三案路线方向均稳健、无根本性制度错误；但案②的 DONE/BLOCKED 必须补 MECE 与优先级、案③必须补停层与层间停让规则，否则机器复核会在边界态失效——补齐即 pass，不补则案②应降为 undecided。
